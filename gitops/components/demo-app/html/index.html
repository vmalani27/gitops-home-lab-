Demo Service HTTP · Port 80

Cluster Deployment Proof

A standalone service running in its own namespace.

This service proves that the cluster can provision an isolated workload using standard Kubernetes manifests. It runs Apache HTTPD inside the demo-app namespace and receives traffic routed through the central Ingress controller.

How this service is wired up

Everything serving this page was created with four declarative objects: a dedicated Namespace, a Deployment running httpd:alpine, a ClusterIP Service, and an Ingress rule on demo.links.test.

Namespace
demo-app
Workload Container
Apache (httpd:alpine)
Internal Service
demo-app-svc:80 (ClusterIP)
Hostname & Protocol
http://demo.links.test

Inspect the deployment

You can check the resources backing this page directly from your terminal:

List all resources in the demo-app namespace.

kubectl get all,ingress -n demo-app

View the ingress routing rule.

kubectl describe ingress demo-app-ingress -n demo-app
